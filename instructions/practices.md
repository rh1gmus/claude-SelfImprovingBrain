# Practices (INSTRUCTION SET: tunable)
Lessons seen in more than one project. Keep each to a line or two. [I-023]

- **Git ownership first.** Before any git command in a repo, run `stat -c %U .git`. If it isn't you, run git as that user (`sudo -u <owner> -H git -C <dir> ...`). [I-024]
  Never add a global `safe.directory`; a "dubious ownership" error means wrong user, not a repo fault. [I-025]
- **Check the repo is live.** Before working in an unfamiliar repo, read its CLAUDE.md or README for "archived" or "deprecated". If it's unclear, ask before changing anything. [I-026]
- **No bare `docker compose up --build`** on a stack with a heavy build stage (e.g. xcaddy). It rebuilds every service with a `build:` section and can take the app down for minutes. Name the service: `up -d --build <svc>`. [I-027]
  On a low-RAM host check `free -m` first, build one service at a time (`COMPOSE_PARALLEL_LIMIT=1`), deploy with `--no-build`. [I-028]
- **Long session logs:** read the tail (`tail -n 80`), not the whole file. Don't load multi-KB logs into context unless asked. [I-029]
- **Files in the scratchpad belong to root.** If another user must read one (commit message, patch), copy it to a location that user can read. [I-030]
- **Redaction needs a test, not eyeballing.** When notes are built from files that may hold secrets, derive notes from structured fields (never raw lines). [I-031]
  Extract the secret literals from the sources (diff redacted vs raw, include text inside docx/xlsx), and search the output tree for them. [I-032]
  Re-run after every redactor change; new secret forms (`PASS=`, `-apiSecret '..'`, `net use /user: "pw"`, value on the line after `password:`) kept slipping through. [I-033]
- **Untrusted or customer downloads:** filter by type and name first, then scan the downloaded content (private-key headers, person columns, device configs) and delete unwanted local copies before analysing. File-name filters alone let sensitive files through. [I-034]
  Check `which gh azcopy az` first; REST with curl/Python works, and a SAS needs `l` (list) plus the Service resource type for account-level listing. [I-035]
- **Test the tests.** After a feature passes, commit (or WIP-commit) it, then break the code on purpose (drop the auth check, remove the escaping) and confirm a test fails; only then is `git checkout <file>` a safe restore. Tests that pass first try often assert too little. [I-036]
- **Probe the running system.** Send the hostile case (a token in a URL, an odd date) to the deployed service and read its logs. Found log leaks and parser gaps that unit tests missed. [I-037]
  Prefer GET: a test POST on a live service ran real work (a job refresh). [I-038]
- **Read the installed library before coding against it.** Check its version and `dir()`; majors rename APIs (mcp 2.x: `MCPServer`), and SDKs may hide error text unless you raise their "expected error" type. [I-039]
- **Never hunt for or print credentials.** Don't read other projects' env files or containers, and don't `cat` a config file while surveying a project: its CLAUDE.md names the secret-bearing files, so read docs first and skip those. [I-040]
  Ask the user to place a secret in this project's `.env`. [I-041]
  Test fixtures use synthetic secrets of the same shape, never real values. [I-042]
- **Assert HTML/XML safety by parsing, not regex.** A regex flags escaped attribute text as a live handler and can miss real breakout. [I-043]
- **No venv on the host?** Don't fight `python3-venv`. Run pytest in `docker run --rm -v "$PWD":/w -w /w python:3.12-slim ...`. [I-044]
- **Branch work on a live repo: use a worktree.** If the checkout is bind-mounted into running containers, or holds the user's uncommitted edits, don't switch branches in it. Use `git worktree add <dir> <branch>` in a dir the repo owner can write (a root-owned parent makes it fail), and test there. [I-045]
  Stage only your own files. [I-046]
  Guard every `cd` with `|| exit`: `set -e` ignores failures inside `&&` chains, so a failed `cd` ran a commit in the live checkout. [I-047]
- **Hardening a container: check `getcap` on its binary.** A file capability (`cap_net_bind_service=ep`) can't be gained under `cap_drop: ALL` plus `no-new-privileges`, so exec fails with EPERM. Strip it, or copy the binary without xattrs. [I-048]
  Test the change in a throwaway project first. [I-049]
- **Re-run a worker's check yourself.** Never accept a subagent's PASS unseen. [I-050]
  For risky work, also run a stricter check the worker wasn't shown (a hidden case); a visible check once passed code that broke on quoted CSV. [I-051]
- **Apps behind a prefix-stripping proxy** need relative links, form actions and redirects; keep gate paths (`/logout`, `/oauth2/...`) absolute. [I-052]
  Behind TLS-terminating gates, server-built redirects say `http://` (Apache: `ServerName https://host` + `UseCanonicalName On`). [I-053]
  Test it by scanning rendered HTML, and confirm the test fails when the fix is reverted. [I-054]
- **Size fixed subnet blocks for growth.** If a deny rule covers a CIDR block (per-tool networks), widen the block and the rule together; one without the other silently drops isolation. [I-055]
- **Existing tests encode decisions.** When a restyle or refactor fails one, change it deliberately and say why. [I-056]
  Prove a failure is old by stashing your change and re-running. [I-057]
- **Merged equals deployed?** Compare `git rev-parse HEAD^{tree}` before and after switching to merged `main`; equal trees mean no rebuild. [I-058]
- **Look at visual changes.** Screenshot with `zenika/alpine-chrome --no-sandbox --headless --screenshot` in docker; the output dir must be world-writable. [I-059]
- **Wrapping a localhost-only tool:** patch the pinned release at build time with a script that fails if a pattern matches other than once; have the proxy rewrite `Host` for its rebinding guard rather than weakening the guard. [I-060]
  Screenshot pages with live streams (SSE) using `--timeout=6000`, not `--virtual-time-budget`, which hangs. [I-061]
- **Prove an image's provenance by rebuilding it.** With no CI access, `docker build` the Dockerfile locally and compare the binary's sha256 with the running one (`docker cp`). A match beats any amount of reading. [I-062]
- **After rebuilding a Docker network, recreate its services.** Containers that merely restart come back without their compose service-name aliases. Use `up -d --force-recreate <svc>`, then check DNS by name (`getent hosts <svc>`), not only by IP. [I-063]
  A plain `up -d` that must change a network's subnet stops its services and then fails while another project's container is attached: `rm -sf` those containers first. [I-064]
