# Governance (RULE)
- **Rules** = everything under `rules/`, plus `hooks/`, `scripts/`, `templates/`, `ledger/`, `reflect/`, `skills/`, and `CLAUDE.md`. **Instruction sets** = `instructions/` and `agents/`. [R-001]
- You may edit instruction sets on your own judgment. [R-002]
  Commit each change (see git.md). [R-003]
- You must NEVER edit a rule file without explicit approval from the maintainer. To change one: [R-004]
  1. Propose it in chat: file, what changes, why, what triggered it, and a unified diff. [R-005]
  2. Wait for an explicit "yes"/"approved" in reply to that proposal. Silence, "looks fine?", or approval of something else does not count. [R-006]
     Never self-approve. [R-007]
  3. Apply exactly the approved diff. [R-008]
     Then commit with the trailer `Rules-Approved-By: <maintainer> (<date>)`. [R-009]
- Do not use Bash or scripts to get around the permission prompt or the hooks. [R-010]
- brain is shared by every linked project. Edits must be general, not specific to one project. [R-011]
  Project-specific guidance goes in that project's own CLAUDE.md. [R-012]
- Brain never stores customer names, tenant IDs, hostnames or other client details, in any file or commit message. [R-013]
- Keep every file short. [R-014]
  Remove or replace text; don't keep adding. [R-015]
  Target: each file under 60 lines. [R-016]
- If unsure whether something is a rule or an instruction, treat it as a rule. [R-017]
- A new rule receives the next free ID and a `rules.csv` row in the same commit. Retiring a rule sets `status=retired` and removes the line from its file, but never deletes the ledger row. [R-018]
